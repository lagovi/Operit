Принципы:
- Целевая локаль — только **English**. Теперь английский лежит в **неквалифицированном `values/`**, а `values-en/` удалён: квалифицированный бакет — это то, куда Android откатывается при любом неразрешённом ссылании и по которому система резолвит подписи в лаунчере, поэтому английский обязан быть дефолтным. Прочие локали (es/ja/ko/…) не заполняем — вне скоупа.
- Ничего не выдумывать вручную: всё через проверяемые скрипты и CI. Не добавлять fallback-логику в код (жёсткое правило проекта).

## 2. Дозаполнение values (новые ключи upstream)

**Механика ниже применима только к новым ключам, которые upstream принёс
китайскими.** Она не покрывает четыре реальных дефекта из
`re-audit-l10n.md`, каждый из которых выглядел бы как «незаполненный перевод»,
но был им не являлся.

Механика «пакетного ИИ-перевода» (уже встроена в tooling):

```bash
python3 tools/string/check_strings.py --export-tsv /tmp/en_missing.tsv   # исходник → tsv для ИИ
# → передать TSV ИИ-агенту на перевод → /tmp/en_missing_filled.tsv (3 колонки: key, src, en)
python3 tools/string/check_strings.py --import-tsv /tmp/en_missing_filled.tsv --lang en
```

- ИИ-агент получает TSV целиком, переводит в стиле существующей en-локали (короткие UI-строки, Title Case для заголовков, сохранять `%1$s`/`%1$d` и термины: Tool Package, Skill, MCP, Workspace, Token, Character Card).
- После импорта: повторный `check_strings.py` → `默认(default): 完整`. Ярлык источника теперь `default`, а не `zh`: квалифицированного бакета с китайским больше нет, и гейт сравнивает по квалификатору, а не по языку.
- Ревью: `git diff app/src/main/res/values/strings.xml | head -100` — проверить формат спецсимволов (`&amp;`, `\'`, `\n`).

**Внимание, это ловушка, в которую попал предыдущий проход.** Гейт
`check_localizations.py` при локали, зашитой на `zh`, после переноса английского
в дефолтный бакет начинал сравнивать все бакеты с английским и называть это
«недостающими переводами» — молча, потому что при единственной локали
сравнивать было не с чем и отчёт оставался пустым. Теперь источник
определяется как неквалифицированный бакет (`SOURCE_LOCALE`), но эти два
скрипта по-настоящему начнут что-то значить только когда появится вторая локаль.

## 3. Экстракция хардкод-китайских строк из кода

Механика по-прежнему нужна — но запускать её нужно по списку из
`ci/script/fork_audit.py` (проверка `CJK-NEW`), а не по
`tools/string/count_ui_strings.py`, который обходит только часть дерева и
пропускает модуль `:terminal`. Именно поэтому 65 строк в `:terminal`
продержались незамеченными: у скрипта не было настроек на этот модуль.

**Оставить как есть (не трогать):**
- матчеры/regex для парсинга (эмоции, роли «用户/助手», «问题/解决方案», regex команд);
- LLM-промпты и тексты, уходящие в контекст модели (даты/дни недели в промптах, суффиксы разметки) — **кроме случаев, когда промпт виден в интерфейсе**: поля waifu, пресеты тегов, подписи инструментов, сообщение сводки в чате, описания пакетов, ошибки Tool Tester;
- сообщения только в лог (AppLogger) и dev-`require()`;
- нативные названия языков, URL, JSON-ключи, HTML-атрибуты, ключи DataStore;
- **имена голосов TTS.** `id` — wire-значение для API вендора, `name` — имя продукта, по которому пользователь ищет голос. Английский псевдоним сделал бы выбор хуже. Решение зафиксировано в `PROMPT-002`.


**Извлекать (пользователь видит):** Text/тосты/ошибки в UI, label'ы в диалогах, contentDescription, сообщения Exception доходящие до UI, подписи в селекторах.

Механика (как в коммите `610d9f0b`):
1. В Kotlin заменить литерал на `stringResource(R.string.<key>)` (composable) или `context.getString(R.string.<key>, args)` (если есть Context в скоупе).
2. Если класса/функции нет Context и это не composable — **пробросить Context параметром, а не оставить строку китайской.** Так пришлось переделать `McpConfigImportParser`: все три места вызова пропускали исключение до пользовательского сообщения об ошибке, и пока у парсера не было `Context`, менять текст было не на чем.
3. Ключ дописать в `values/strings.xml` **с английским текстом** — это единственный строковый бакет приложения. `values-en/` больше не существует; во втором бакете ключ окажется неопределённым и соберётся как ссылка на несуществующий ресурс.
4. Приватные non-composable хелперы, вызываемые только из composable, можно пометить `@Composable` и использовать `stringResource`.

**Ловушки компиляции (словлены трижды — проверять статически до пуша):**
- `stringResource` НЕЛЬЗЯ внутри `try/catch` → выносить все вызовы наружу (пример: `relativeTime` в UnifiedMarketScreen).
- `stringResource` НЕЛЬЗЯ в `LazyListScope`-лямбде (тело `LazyColumn { }`, `groupedMarketItems`) → вычислить выше и передать параметром.
- `stringResource` принимает `Any`, а не `Any?` → nullable-поля надо разрешать на месте вызова через `?:`. Строка интерполяции с nullable молча компилировалась, формат-ресурс — нет.
- Не собирать подписи конкатенацией: `stringResource(X) + ":"` и `"${stringResource(X)}: $v"` оба закрыты как класс дефекта и проверяются гейтом `LABEL-CONCAT` в `fork_audit.py`.
- `stringResource` можно в inline-лямбдах (`ifEmpty`, `let`, `when`).
- `@Composable`-функцию нельзя вызывать из non-composable кода.
- Если поменял тип таблицы вариантов (`List<Pair<String,String>>` → `List<Pair<String,Int>>`), обнови ВСЕ использования (`grep`).

## 4. Edge-to-edge / читаемость

Приложение edge-to-edge (`Theme.kt: setDecorFitsSystemWindows(false)`). Основной контент защищён инсетами в `AppContent.kt`, а экраны вне него — нет. На устройстве это = нижние кнопки под системной навигацией, недоступные и невидимые.

## 7. Верификация на устройстве

Всё через `uiautomator dump` + grep; скриншоты могут не читаться. Готовый
скрипт: `ci/script/verify_device.sh [--fresh]`.

**`--fresh` обязателен.** Значения вроде имени конфигурации модели, wake-фразы
и группы чата записываются в DataStore при первом запуске — на языке, который
тогда был активен. Установка поверх старой восстанавливает их из бэкапа, и
проверка выглядит провалившейся из-за значения, сохранённого ещё до правки.

1. `adb shell pm clear com.ai.assistance.operit.debug`, затем запуск. Системная
   локаль телефона — `ru-RU`, то есть неподдерживаемая. Первый экран обязан быть
   английским: это и есть проверка дефекта локали по умолчанию.
2. `LC_ALL=C.UTF-8 grep -oP '[\x{4e00}-\x{9fff}]+' dump.xml` — пусто на каждом
   экране.
3. `adb shell dumpsys notification --noredact | grep -oP 'mName=[^,}]*'` — в именах
   каналов Operit не должно быть CJK. **Проверять обязательно:** имя канала
   захватывается системой при первом создании и больше не меняется, поэтому
   установка, первый запускавшаяся под другим языком, будет показывать чужой
   язык в настройках системы навсегда, независимо от кода. Лечится только
   версионным суффиксом в id канала (см. `L10N-006`).
4. Toolbox, Model Config, шторка модели, список пакетов — при максимальном
   встроенном масштабе шрифта (1.5), а не при 1.0. Фиксированные высоты
   верны при 1.0 и режут глифы при 1.5.
5. Сквозной тест ИИ: включить автосоздание чата (см. шпаргалку), отправить
   запрос → в `files/logs/operit.log` хвост: `回合完成`,
   `TokenStatisticsDelegate … Input/Output` — конвейер работает. (Это лог, а не
   UI, поэтому он остаётся китайским — так и должно быть.)
6. Локально: `python3 ci/script/fork_audit.py` — ноль расхождений; отчёт
   `check_strings.py` теперь `默认(default): 完整`.

## Телефон: шпаргалка (критично, экономит часы)

- **Ввод текста**: Samsung IME ДУБЛИРУЕТ каждый символ при `input text` и бродкастах ADBKeyboard. Приём: ввести, затем ровно столько backspace (keyevent 67), сколько лишних (1 backspace = удаляет 2 символа). ADBKeyboard (`com.android.adbkeyboard/.AdbIME`) принимает `am broadcast -a ADB_INPUT_TEXT --es msg 'word'` (без пробелов; с пробелами ломает парсинг am).
- **Патч DataStore через run-as** (app force-stopped): proto формат Preferences: верх = repeated Pair(1); Pair = string name(1) + Value value(2); Value = вложенное сообщение (bool→field1 `0x08`, string→field2 `0x0a`). Скаляр напрямую в Pair писать НЕЛЬЗЯ — будет `CorruptionException: Value not set` и краш приложения. Рабочий пример bool-true: `0a190a13<19 байт имени>12020801`. Скрипт-пример: `/tmp/patch_model_config.py` (на машине агента).
- **Координаты тача**: dump-пространство 0..1422 при экране 720x1560; для полноэкранных окон/диалогов physical_y = dump_y + 54; для главного окна чата — как правило raw. Пробовать оба варианта. Тап по координатам берём из bounds узла.
- **uiautomator dump** периодически отдаёт старое/пустое (`null root node`, `already registered`): всегда сверять, что дамп изменился (размер/контент), прежде чем делать вывод «тап не сработал».
- Экран гаснет быстро: `adb shell settings put system screen_off_timeout 600000`; пробуждение: `input keyevent KEYCODE_WAKEUP` + `82`.
- Системная локаль телефона ru-RU; приложение берёт язык из своей настройки (datastore `app_language`) — en применяется при старте.
- Remote-объявление (公告) приходит с апстрим-сервера на китайском — это НЕ ресурсы приложения, не «исправлять» в коде.
